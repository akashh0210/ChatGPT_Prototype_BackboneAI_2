## 1. Product overview

**Backbone** is a calibration layer woven into ChatGPT's response. Instead of producing a single polished answer that users have to trust on faith, Backbone surfaces — inline with the answer — the reasoning behind it, the assumptions it made, the confidence behind each specific claim, and a self-critique flagging what to verify.

The architecture intentionally separates the *answer generator* from the *evaluator*. The self-critique is generated by a separate evaluation pass, not by the model that wrote the answer. Every confidence marker is paired with the reasoning that produced it. The user remains in control of judgment at every step.

**This PRD covers a functional prototype:** a single-page web app, ChatGPT-faithful in visual design, that makes real Grok API calls when the user clicks one of four preset prompts. Each preset triggers a full Backbone pipeline (generation → evaluation → calibrated response render) producing a real LLM-backed response with real reasoning, real confidence markers, and a real critique.

## 2. Scope

### In scope (v1)
- Single-page web app with **ChatGPT 2025 visual fidelity** — dark theme, sidebar, header, input bar, response area, all styled to match the actual current ChatGPT interface
- **Four preset quick-prompt buttons** displayed prominently, each triggering a real Grok-backed Backbone response on a curated scenario
- **Input bar visible but disabled** — preserves ChatGPT look without enabling free-form prompts (cost containment)
- **Real Grok API integration** with two distinct model passes:
  - **Generation pass:** Grok-4 with a "primary assistant" system prompt produces the answer + reasoning + assumptions
  - **Evaluation pass:** Grok-4-Fast (or different Grok model) with a "critical evaluator" system prompt produces the confidence markers + critique
- **Streaming responses** — the answer streams in word-by-word using real Grok streaming, not faked typewriter delay
- **Sequential reveal** — reasoning trace appears first, then streamed answer, then confidence markers, then assumptions, then critique footer
- Interactive Backbone features: collapsible reasoning trace, editable assumption tags, expandable self-critique footer with three issue cards per response
- Replay/regenerate button to re-run the most recent preset
- Public deployment via Vercel
- Public GitHub repo with a clean README
- Serverless backend route to keep API key off the client

### Out of scope (deferred)
- Free-form user input (input bar is decorative)
- Multi-conversation history (sidebar items are decorative)
- User authentication or account state
- Saved/shared responses
- Mobile responsive design (desktop only for v1)
- Antigravity port (post-deck-submission stretch goal)
- Analytics or telemetry beyond basic error logging

## 4. The four preset prompts

Each preset triggers a real Grok call and produces a real Backbone-formatted response. The presets are chosen to demonstrate Backbone catching *different kinds* of failures, not just one.

### Preset 1 — Research summary
**Label:** "Summarize remote work productivity research"
**Prompt:** "Summarize the latest research on remote work productivity, including its impact on output volume and team dynamics."
**Why this scenario:** Demonstrates Backbone catching **fabricated citations** and **evidence overreach** — a common failure mode in research summaries.

### Preset 2 — Technical explanation
**Label:** "Compare RAG vs fine-tuning"
**Prompt:** "Explain the practical differences between Retrieval-Augmented Generation (RAG) and fine-tuning for adapting an LLM to a specialized domain. Which should a startup use?"
**Why this scenario:** Demonstrates Backbone catching **assumption-laden recommendations** — technical advice that sounds confident but depends on unstated context.

### Preset 3 — Decision-making
**Label:** "Evaluate a job offer trade-off"
**Prompt:** "I have two job offers. Job A pays 30% more but is at a less stable company. Job B is at a top-tier firm but the role is more junior. Which should I take?"
**Why this scenario:** Demonstrates Backbone catching **over-personalized advice** — confident decision recommendations that ignore unknown personal context.

### Preset 4 — Work analysis
**Label:** "Critique a product strategy"
**Prompt:** "Critique the following product strategy: 'We will become the leading AI assistant for healthcare by focusing on superior accuracy and faster responses than competitors.'"
**Why this scenario:** Demonstrates Backbone catching **shallow analysis** — surface-level critiques that miss deeper strategic considerations.

### Preset UI
- Four buttons displayed in a 2x2 grid (or horizontal row, depending on layout) prominently placed where users would normally type
- Each button has a short label (5-6 words) and a small icon indicating the category
- Clicking a button immediately triggers the API call and runs the full Backbone pipeline
- After a preset is run, the buttons remain visible so users can try another

## 5. Grok API integration

### API access
- **Provider:** xAI (console.x.ai)
- **Models used:**
  - `grok-4-latest` for the generation pass (primary, full reasoning capacity)
  - `grok-4-fast-non-reasoning` for the evaluation pass (cheaper, faster, different "persona")
- **API spec:** OpenAI-compatible — use the OpenAI SDK pointed at Grok's endpoint or call Grok's REST API directly
- **Endpoint:** `https://api.x.ai/v1/chat/completions`
- **Authentication:** Bearer token via `Authorization` header
- **Streaming:** Set `stream: true` in the request body to enable streaming

### Critical security requirement
**The Grok API key MUST live on the backend only.** Never expose it in client-side code, never commit it to the repo, never include it in the bundle.

- Store as `GROK_API_KEY` in Vercel environment variables
- Access only from the serverless function (`/api/backbone`)
- Add `.env.local` to `.gitignore`
- Use a `.env.example` with placeholder for the README

### Generation pass — system prompt template
The generation pass uses Grok-4 with a system prompt that instructs the model to produce structured output containing reasoning steps, the main answer, and explicit assumptions.

```
You are ChatGPT, a helpful AI assistant. For each user question, produce a response in the following JSON structure:

{
  "reasoning_steps": [
    "Step 1: brief description of what you considered first",
    "Step 2: brief description of the next consideration",
    "Step 3: brief description of the final consideration"
  ],
  "main_answer": "Your full answer here, written as natural prose. Aim for 100-180 words. Make specific claims where appropriate.",
  "assumptions": [
    "An assumption you made about the user's context (e.g., 'Assumes post-2020 data')",
    "Another assumption you made (e.g., 'Assumes general knowledge workers, not specific roles')"
  ]
}

Reasoning steps should be concise — what process you used to arrive at the answer.
Main answer should sound natural and confident, like a normal ChatGPT response. Do not hedge unnaturally.
Assumptions should name the implicit context you assumed. Aim for 2 assumptions per response.

Return ONLY the JSON object. No surrounding text.
```

### Evaluation pass — system prompt template
The evaluation pass receives the generation pass's output as input context, and runs a *different model* (Grok-4-Fast) with an evaluator-persona system prompt.

```
You are an evaluation model whose job is to critique an AI-generated response and identify weaknesses the user should be aware of. You are NOT the same model that wrote the response — you are an independent evaluator.

You will receive an AI response in JSON format with reasoning, a main answer, and assumptions. Your job:

1. Identify 3 specific claims in the main answer and assign each a confidence level:
   - HIGH: well-supported, consistent across sources, robust claim
   - MEDIUM: plausible but with caveats — methodology varies, context-dependent, etc.
   - UNVERIFIED: cannot confirm in training data, specific figures that may be fabricated, overreaching conclusions

2. For each confidence marker, write a SHORT REASON (one sentence) explaining why you assigned that level.

3. Identify exactly 3 issues with the response. Each issue must be one of three types:
   - SOURCE_VERIFICATION_NEEDED: specific facts, citations, or numbers that cannot be confirmed
   - EVIDENCE_OVERREACH: a conclusion stronger than the evidence supports
   - MISSING_CONTEXT: an important caveat, condition, or nuance the response omits

Return ONLY the following JSON structure:

{
  "confidence_markers": [
    {
      "claim_substring": "exact substring from the main_answer text — must appear verbatim",
      "level": "UNVERIFIED | MEDIUM | HIGH",
      "reason": "one-sentence explanation"
    }
  ],
  "issues": [
    {
      "type": "SOURCE_VERIFICATION_NEEDED | EVIDENCE_OVERREACH | MISSING_CONTEXT",
      "title": "Bold one-line title of the issue",
      "explanation": "1-2 sentences explaining why this is flagged",
      "action_label": "Search for source | Show the original evidence | What context is missing?"
    }
  ]
}

Return ONLY the JSON object. No surrounding text.
```

### Frontend rendering of evaluator output
The frontend receives the evaluator's `confidence_markers` array and matches each `claim_substring` against the rendered main_answer text. When a match is found, a pill is rendered inline at that position with the level + reason (reason shows as a tooltip on hover).

The frontend receives the evaluator's `issues` array (always 3 items) and renders them as the three issue cards in the self-critique footer when expanded.

### Error handling
- If the Grok API call fails: show a clear error message in the response area ("Couldn't reach Grok — try again") with a retry button
- If the JSON returned is malformed: fall back to a "static demo" mode using a pre-stored response (one per preset)
- If a rate limit is hit (HTTP 429): wait 2 seconds, retry once, then surface the error

### Cost estimate
At Grok's current pricing (~$5/M input tokens, ~$15/M output tokens for Grok-4; cheaper for Grok-4-Fast):
- Per request: ~3000 input tokens + ~1500 output tokens combined across generation + evaluation ≈ $0.03-0.05 per request
- Expected demo usage: probably 50-200 requests during testing, demo prep, and graders running it ≈ $1.50-$10 total
- Set a low monthly cap on the API key (e.g., $20) for safety

## 6. The four Backbone features (rendering specs)

These are the visual components rendering the API output.

### Feature 1 — Reasoning Trace
**Renders:** the `reasoning_steps` array from the generation pass

**Behavior:**
- Appears at the top of the assistant response, collapsible
- Defaults to expanded on first view of each response
- Toggle: "hide reasoning" / "show reasoning"
- Steps displayed as a numbered list with green badge circles

**Styling:**
- Card with subtle gradient background (#2A2B32 → #25262C)
- 1px border #353641, border-radius 12px
- Header in green (#10A37F) with small dot accent to the left
- Soft shadow

**Maps to brief:** How outputs are evaluated.

### Feature 2 — Main Answer with inline Confidence Markers
**Renders:** the `main_answer` string from generation pass + `confidence_markers` array from evaluation pass

**Behavior:**
- Main answer streams word-by-word as Grok produces it
- After streaming completes, confidence markers fade in inline at the positions matched by `claim_substring`
- Each marker has a tooltip showing the `reason` from the evaluator

**Styling for confidence pills:**
- UNVERIFIED: bg #D97757 with 20% opacity, border #D97757 at 40% opacity, text #D97757
- MEDIUM: bg #E5A155 with 20% opacity, border #E5A155 at 40% opacity, text #E5A155
- HIGH: bg #10A37F with 20% opacity, border #10A37F at 40% opacity, text #10A37F
- Full pill shape (border-radius 12px), padding 2px 8px, font-size 11px, font-weight 500, all caps
- Tooltip appears on hover with the reason text

**Maps to brief:** How confidence is communicated.
**Critical defense against "trust score" anti-pattern:** Each pill is anchored to a specific claim and carries reasoning. There is no aggregate score for the whole answer.

### Feature 3 — Assumption Surface
**Renders:** the `assumptions` array from generation pass

**Behavior:**
- Appears after the main answer
- Each assumption is shown as a tag with a small edit pencil icon
- Clicking the pencil is decorative for v1 (no actual editing)

**Styling:**
- Same card styling as Reasoning Trace
- "Assumptions I made:" header in green with dot accent
- Assumption tags: bordered pills with #353641 border, padding 6px 12px, border-radius 8px

**Maps to brief:** How uncertainty is surfaced.

### Feature 4 — Self-Critique Footer
**Renders:** the `issues` array from evaluation pass

**Behavior:**
- Appears at the bottom of the response
- Collapsed by default: header "Here's what to verify before using this →" with each issue title as a brief bullet
- Subtitle: "Generated by a separate evaluation pass · Always paired with reasoning"
- Clickable to expand: shows three issue cards
- "Collapse" link below cards returns to bullet view
- When expanded, header reads: "3 issues flagged · Backbone caught these before you did."

**Issue card styling (when expanded):**
- Each card has a 3px-wide left-border accent in the issue's type color:
  - SOURCE_VERIFICATION_NEEDED: #D97757
  - EVIDENCE_OVERREACH: #E5A155
  - MISSING_CONTEXT: #5B8DBE
- Type label at top: uppercase, colored to match border, font-weight 500
- Title: white, bold, 15px
- Explanation: muted, 14px, line-height 1.6
- Action button: ghost-style button with 1px border in the card's accent color, padding 8px 16px

**Maps to brief:** How users stay in control of judgment.

## 8. Sequential reveal animation (with real streaming)

The animation timing now depends on the *actual* Grok API streaming, not a faked typewriter. This makes the timing variable but feels more authentic.

### Stage sequence

| Stage | Trigger | Visual |
|-------|---------|--------|
| 0 | User clicks preset | Loading dots appear in response area |
| 1 | First chunk of generation pass arrives (reasoning_steps parsed) | Reasoning trace block fades in (600ms, 20px slide-up) |
| 2 | main_answer field starts streaming | Words appear in main answer area as they arrive from Grok; cursor blinks at insertion point |
| 3 | Generation pass completes; evaluation pass response arrives | Confidence markers fade in inline at matched positions (staggered 250ms, scale 0.85→1.0) |
| 4 | After confidence markers complete | Assumptions block fades in (600ms, 20px slide-up) |
| 5 | After 400ms delay | Self-critique footer fades in (600ms, 20px slide-up) |
| 6 | All visible | Full interactivity restored |

### Real streaming implementation
- Use Grok's streaming response (server-sent events)
- The backend forwards stream chunks to the frontend via a ReadableStream
- The frontend parses streaming JSON incrementally — when `reasoning_steps` is complete, trigger Stage 1; when `main_answer` starts populating, trigger Stage 2 with real word arrival
- Total response time will vary (3-8 seconds depending on Grok latency)

### Replay button
- Top-right of response area
- Resets all rendered Backbone elements
- Re-runs the same preset (does NOT call API again — caches the previous response for replay, to save costs)
- Spinner during reset, then re-runs the animation

### Reduced motion
- If `prefers-reduced-motion: reduce` is set, all stages appear immediately with no transitions
- Streaming still happens (it's content delivery, not decoration)

## 12. What this prototype is NOT

Re-stating the brief's anti-patterns and how Backbone explicitly avoids each:

- **Not a trust score.** Confidence is one of three discrete labels (UNVERIFIED / MEDIUM / HIGH), anchored to specific claims, paired with reasoning. There is no aggregate "this answer is 73% trustworthy" percentage anywhere.
- **Not a separate panel.** All four features live inside the response, in the same surface the user is already reading.
- **Not a fact-checker.** Backbone doesn't verify external sources — it surfaces what to verify and what the evaluator found weak, then lets the user decide.
- **Not a refusal mechanism.** Backbone never blocks responses; it always delivers, with calibration cues attached.
- **Not autonomous AI evaluating AI in a black box.** The evaluator is *a different Grok model* from the generator. Its reasoning is visible to the user in every confidence marker and every issue card. The user always sees *why* something was flagged.
